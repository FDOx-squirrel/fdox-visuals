# fdox-visuals

Presentation and paper graphics for the [FDOx-squirrel](https://github.com/FDOx-squirrel)
family — generated by pure-Python scripts, no external CLI tools required.

## What this is

```
py/step_*.py        geometry + text (no rendering logic)
      │
      ▼  main.py
img/<category>/     SVG source + PNG, versioned (8 topic folders)
      │
      ▼  resvg-py (in-process, no rsvg-convert/ImageMagick/libcairo needed)
      │
      ▼  step "site"
docs/               GitHub Pages: overview + one page per topic
```

Published site: <https://fdox-squirrel.github.io/fdox-visuals/> (GitHub Pages,
branch `main`, folder `/docs`).

The graphics are sorted by topic into `img/<category>/`; every file comes as
`.svg` and `.png`:

| Folder | Content |
|---|---|
| `img/pattern/` | four-step and purpose banners with their badges |
| `img/schemas/` | MD.cff and CITATION.cff schemas, fdo-squirrel architecture, FDO meta graphic and sphere |
| `img/talk-process/` | talk slides, one per step (step 1 also with CIIC 81) |
| `img/talk-purpose/` | talk slides, one per outcome |
| `img/talk-closing/` | closing slides (ring of eight badges, two variants) |
| `img/story/` | the story slides: FKGE map, two roads one bundle (two variants), Squilly graph (draft) |
| `img/git-packager/` | concept graphics for `fdo-git-packager` (draft) |
| `img/federation/` | finished 3D and software FDOs in the federated KG ecosystem (draft) |
| `img/ogham-graph/` | graph pictures of Ogham stones, 3D FDOs and software (draft) |

The folder of a graphic follows from its file name: the rules live in
`CATEGORIES` in `py/visuals_utils.py`, the captions of the site in
`py/site_meta.py`. `img/source/` holds the screenshots the talk slides embed.

## Usage

```cmd
pip install -r requirements.txt
python main.py
```

```cmd
python main.py --list                    show the four steps
python main.py --only fdo-meta            rebuild one graphic
python main.py --only site                rebuild docs/ from the finished img/
python main.py --from architecture        this step and everything after
python main.py --skip md-cff-schema       everything but this
python main.py --dry-run                  print the plan, run nothing
python main.py --strict                   warnings become errors (what CI would run)
```

Running it twice produces byte-identical output; `git status` stays clean
after the second run.

## Design

Colour and type live in one place, `py/visuals_utils.py` — every step
imports from there rather than repeating a hex code. The FDOx blue,
`#004473`, is sampled from the original FAIR Digital Object reference
diagram; Step 1 of the four-step pattern and the FDO meta-graphic share it
so the two graphics read as one family.

Typeface is [Fira Sans](https://github.com/mozilla/Fira) (Mozilla, SIL Open
Font License 1.1), vendored under `fonts/` — a fresh clone renders
identically without the font being installed on the machine that runs it.

Every PNG is cropped to its content plus an exact 10px transparent border
(`trim_transparent_border()`), and kept in the low single-digit megapixels
— large enough to look sharp on any screen, small enough to stay well
under Google Slides' 25-megapixel insert limit, which otherwise silently
re-compresses (and visibly blurs) anything larger.
